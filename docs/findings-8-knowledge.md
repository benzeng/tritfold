## 4. 主结论：1.75bpw 的知识天花板

三轮证据链闭合：v0.2（聊天蒸馏不动似然排序）→ v0.3（教育语料修好格式纪律、字母知识仍硬币）。12M token 级的泛教育蒸馏无法重建被三值压缩抹掉的知识表征；FP 的生成式 0.733 与三值的 0.227 之间的差距是**容量问题**，不是数据配方问题。可及的下一步（按杠杆排序）：① 知识语料 ×10 量级（120M token 级，缓存架构已支持流式）；② 规模效应（7-8B，需 80GB 或分片）；③ RAG/检索外挂（绕过容量约束的工程解）。

### chat 协议的第三层发现（补全矩阵后）

- **FP 字母知识真值 = 0.789**（chat 已解析子集，高于裸格式 0.733）——它"想解释"（未解析样例全是被 8 token 截断的推理开头 "The question asks about..."），吐字母时几乎必对；
- **v0.3 在 chat 协议下 86% 输出为空**：模型在 ultrachat 训练中学到"空 think 块 → 简短作答"的关联，我们强制的空 think 闭合直接触发 EOS。v0.2 时代的 `<think>` 残留从"化妆问题"升级为"协议杀手"——v0.4 若走 chat 路线必须先清洗训练目标里的空 think 块；
- **知识天花板最终定论**：三协议（似然/裸生成/chat 生成）无任何一格显示三值模型具有超随机的字母知识，而 FP 在两格 0.73-0.79——容量瓶颈，证据链闭合。

## 5. Phase 0 的方法论副产物：两个评估伪影（立档）

1. **"OKAY→A" 解析伪影**：chat 格式下 enable_thinking kwarg 被 apply_chat_template 忽略 → FP 自开 `<think>` 被截断 → 逐字符解析器在 "OK-A-Y" 中抓到 A → 197/200 全选 A、acc=0.224 假数据。修复：手动追加 `<think>\n\n</think>\n\n` 强制闭合 + 严格正则解析。**教训：自动解析评估必须带输出分布审计（字母直方图 3 分钟拆穿）**；
2. **fp16 无罪证明**：本机 fp16 裸格式 FP = 0.733 与 A100 bf16 逐位一致——生成式字母任务的精度鲁棒性高于 ppl（与 fp16 对 ppl 的 1.4× 通胀形成对照）。
