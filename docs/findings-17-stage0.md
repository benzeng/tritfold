- 结论：**8B @ A100-40GB 定案配方 = Z bf16 + PagedAdam8bit + 梯度检查点 + CHUNK=4**；A2 臂实测 loss 降幅 45.8%（REF 46.5%，相对 98.6%）、peak 30.4GB（余量 9GB）、bf16 无停滞

## 1. 四轮淘汰史（每一轮的尸体都是账本教训）

| 轮 | 配置 | 死因 | 账本修正 |
|---|---|---|---|
| R0-REF | 1.7B fp32-Z | ~~发散~~（脚本漏 clip_grad_norm） | 配方组件不可漏抄——烟测也必须完整复刻 |
| R1-A | 8B bf16 + Paged，无检查点 | GPU OOM：硬占用 41.4GB | **F.linear 反传图扣留物化 w**（STE 的 w 全量驻图：REF peak 20.1 = 6.8×3 对账）→ 真实下限 3×Z |
| R2-B | 8B bf16 + 检查点 + CPU fp32 master | **系统 RAM 崩**：master 30.3 + Adam m/v 60.6 = 91GB > 83GB | CPU 侧优化器状态必须入账 |
| R3-A2 | 8B bf16 + Paged + **检查点** | 存活 | 检查点使 w 反传时重算 → 硬占用 3×→2×Z；分页态 15.2GB 统一内存可迁主机（R1 死于硬占用先撞顶，分页没机会救场） |

## 2. 判据读数（A2 vs REF）

- loss：13.13 → 7.11（45.8%）vs REF 12.67 → 6.78（46.5%）——**轨迹同形**
- bf16 ulp 疑虑（|Z|~0.05 处 ulp ≈3.9e-4 vs 更新 2e-4）未成真：50 步内与 fp32 不可区分。残留风险（5000 步累积漂移）由 Stage 1 的 ppl 门兜底
- 速度 18.56s/step @ CHUNK=1（含检查点重算 ~1.33× 与分页迁移）；Stage 1 用 CHUNK=4 预计 ~10s/step

## 3. 工程沉淀（AGENTS 已录）

- **双端账本**：GPU（参数+梯度+图留张量+优化器态+激活+logits）与 CPU RAM（master+优化器态+缓存）都要算
- 物化权重的图驻留是隐形成本，梯度检查点是最廉价的解法
- PagedAdam8bit 的分页态在硬占用接近上限时才可靠工作——留 ≥8GB 余量
