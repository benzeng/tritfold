## 4. 工程坑立档（全部集中在"状态转移"环节，各修一处根治）

1. **Python 3.11+ IntEnum 坑**：`str(枚举).endswith("PTQ1_0")` 在 3.10 = 类名拼接 ✓、3.13 = "143" 恒假——本机全绿、Colab 静默零写入（自举恢复 ppl 577k 的元凶）。修：`int(t.tensor_type) == 143` + 恢复计数断言（196/1/113 不满即停）；
2. **gguf 包双源坑**：PyPI gguf 不含 Prism 私有类型（142/143），需 fork 的 gguf-py（浅克隆 + 非 editable 安装；`-e` 在 Colab 偶发注册失败）；
3. **步数空间坑**：保存节流基准误用 M4 的 `ck["step"]=4700`，M5′ 步数 1..3000 下区间条件永假 → 终点外零保存。修：基准归零。用户盯出（`[Drive 同步]` 未出现）。
4. （前轮已修）GGUF 预取必须在切离线之前；env cell 旧断言残留。

**方法论教训**：本机验证必须覆盖 (a) 目标环境差异（Python 版本）、(b) 行为级验证（前向 ppl），仅权重级对比（bit-exact）不足以放行。
